# 软件实测审核记录（2026-10-07）

用 Windows UI 自动化把融合版软件**从头到尾点了一遍**（选择照片 → 检测 → 切图 → 实验记录 →
设备连接 → 模型与数据管理 → 3D 模拟），把发现的问题如实记录在这里。

环境：Windows 深色模式（`AppsUseLightTheme = 0`），屏幕 1536×864。

## 一、致命问题：深色模式下数据全是"白字白底"

| 项目 | 内容 |
| --- | --- |
| 现象 | 主界面的孔位表、实验记录表**数据行完全是空白**（表头正常），模型与数据管理窗口的说明文字看不见 |
| 根因 | 应用样式表把表格背景设成 `white`，但**没有设置文字颜色**；Windows 深色模式下系统文字是白色 → 白字白底 |
| 影响 | 用户根本看不到孔号/置信度/圆心坐标，等于核心结果不可读 |
| 修复 | 给 `QTableWidget` / `QTableWidget::item` / `QHeaderView::section` / `QComboBox` / `QProgressBar` / 全局 `QLabel` 显式加上深色文字；Tkinter 管理窗口统一配置 ttk 颜色 |
| 涉及文件 | `inspection_gui/gui.py`、`records_view.py`、`devices_view.py`、`app.py` |
| 验证 | 修复后表格显示 H01 0.9642 / 1318.37,1101.31 等，全部清晰可读；主界面原本看不见的"圆心/箱体定位/缩放"也恢复 |

> 这是本次发现的最严重问题：**功能其实是对的，但数据看不见**。

## 二、选择照片总是打开"程序安装目录"

| 项目 | 内容 |
| --- | --- |
| 现象 | 点"离线测试 · 选择照片"，文件对话框停在软件自己的安装目录 |
| 根因 | 代码写死 `initialdir=r'C:\训练照片（箱体）'`（作者机器上的路径）；该目录不存在时 Windows 静默回退到当前目录 |
| 修复 | 改为"记住上次用过的文件夹"（存 `last_photo_dir.txt`），首次使用回退到"图片"文件夹 |

## 四点五、第二轮界面优化（参考 DobotStudio Pro 的样式）

用户提供了 DobotStudio Pro（CR5A 真机软件）截图作为参考，据此做了以下改动：

| 项目 | 改动前 | 改动后 |
| --- | --- | --- |
| **3D 模拟的机械臂** | 直筒圆柱 + 平色环，不像真实协作机器人 | **CR5A 样式**：底座立柱 + 蓝色装饰环、锥形臂身、圆角关节毂 + **蓝色关节环**、腕部三联关节、深色末端法兰 |
| **3D 场景配色** | 深蓝背景、深色台面 | **浅色背景**（贴合 DobotStudio 的白色网格地面观感）、浅灰台面、细描边让白色部件仍有轮廓 |
| 3D 场景标签 | 贴边被裁 | 自动收进视口内，不再被裁 |
| 孔位表列宽 | 5 列固定宽度（约 510 px）→ 最后一列被切、出现横向滚动条 | 小列按内容自适应、坐标列占满剩余宽度 → **不裁切、无横向滚动** |
| 设备连接窗口 | 固定 760 高 + 固定表格高度 → 底部按钮被裁 | 按屏幕自适应高度、表格高度 273→214 |

> 3D 仍然是**示意几何**（不是真实运动学），界面里也保留了"示意模型／非实机轨迹"的说明。

**功能取舍（我做的判断）**

| 处理 | 内容 | 理由 |
| --- | --- | --- |
| **突出为主操作** | 选择照片 / 开始检测 / 发送测量任务，编号 ①②③，蓝色实心按钮 | 这是每次都要走的流程 |

| **收进弹窗** | 添加训练数据 / 训练验证结果 | 属于"模型与数据管理"的子流程 |
| **保留** | 孔位表、双击放大、诊断信息、快捷键 Ctrl+O / F5 | 核心能力 |
| **新增** | 顶部标题栏（应用名 + 副标题 + 模型状态）、图像浅色画布、右侧状态卡 | 让界面像"软件"而不是"脚本工具" |
| **改动** | 画布由深蓝渐变改为浅色；表格取消网格线、改斑马纹；按钮统一圆角与主次样式 | 与浅色界面统一 |

### 环境事实复核（2026-10-08）

- `torch 2.5.1+cu121`，`torch.cuda.is_available() = True`，
  设备名 `NVIDIA GeForce RTX 3050 Ti Laptop GPU`，`ultralytics 8.4.173`
- 桌面快捷方式「机械臂孔检测系统」→ `robot_inspection\.venv\Scripts\pythonw.exe app.py`

  不会出现"两套环境"的问题
- **不要同时开两个软件实例**：两个窗口会同时读写 `last_batch.json` / `batches\`，
  容易看着像"上次的检测结果没清掉"
- 说明：这个 venv 是用 `E:\Miniconda3\python.exe -m venv` 建的，用 `pythonw.exe` 启动时
  会再拉一个 `E:\Miniconda3\pythonw.exe` 子进程（实际加载的仍是 venv 里的包）。
  功能正常，属 conda 建 venv 的正常现象，不是故障。
