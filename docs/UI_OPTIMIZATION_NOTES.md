# 朋友版界面优化建议（附我方界面的取舍）

日期：2026-10-07
对象：朋友的「双机械臂孔检测系统」（`E:\robot_project\friend_engine_local`）

---

## 一、他界面的优点（先说好的）

1. **功能完整**：离线测试、设备连接、实验记录、模型与数据管理，都在一个窗口里。
2. **老实**：右侧直接写「孔号按当前图像位置排序；尚未建立固定物理孔身份」。
3. **有 part 模型**：会拿工件轮廓筛掉不属于这个工件的孔——这是我们的版本没有的能力。
4. **一键标注 → 增量训练**：不离开软件就能补数据、重训，闭环做得比我们完整。

---

## 二、必须改的问题（按严重程度）

| 优先级 | 问题 | 现象 | 建议 |
| --- | --- | --- | --- |
| **P0** | **窗口宽度超出屏幕** | 1550×830 的屏幕上，右侧「孔位与测量准备」面板被截断，表头和文字看不全 | 用 `QScrollArea` 包右栏，或改成可拖动的 `QSplitter`；把最小宽度限制在 ≤1280。**这是目前最影响使用的问题** |
| **P0** | 顶部 5 个按钮平级、没有主次 | 用户不知道该先点哪个 | 改成流程化编号：`① 选择照片 → ② 开始检测 → ③ 查看/导出结果`，设备/记录/数据管理收到左侧导航栏 |
| P1 | 没有进度反馈 | 检测时只有"系统就绪" | 加进度条 + "第 3/7 张" + 预计剩余；检测放到 `QThread`，避免界面假死 |
| P1 | 低置信度没有视觉提示 | 0.68 和 0.99 显示一样 | 置信度列按阈值上色（≥0.9 绿 / 0.75~0.9 黄 / <0.75 橙），并加 `⚠` 图标 |
| P1 | 拟合结果无法快速核对 | 只能看数字 | 表格双击某一行 → 弹出该孔的放大裁剪图（椭圆+中心+长短轴），我们版本已有这个功能 |
| P2 | 出错用弹窗 | 打断操作 | 改成底部状态栏文字 + 可展开的日志面板 |
| P2 | 坐标系不直观 | 只有像素数字 | 画布上加坐标网格/比例尺，鼠标移动显示当前像素坐标 |
| P2 | 结果导出弱 | 只有 CSV | 生成一页 PDF/图片质检单（原图 + 标注 + 表格 + 时间 + 模型版本） |
| P3 | 配色 | 深蓝画布 + 浅色面板，对比尚可 | 统一深色主题或统一浅色主题，别混搭；按钮 hover/disabled 状态要明显 |

---

## 三、比"改界面"更值钱的三个功能建议

1. **模型/方案对照视图**：同一张图并排显示"他的模型 / 我们的模型 / 双模型融合"三列结果
   （他早期版本有这个，整合版砍掉了；其实是这个项目最有说服力的演示）。
2. **标定面板**：把"像素圆心 → 机器人坐标"做成界面可见的一步（现在只有像素坐标，
   用户很容易误以为可以直接拿去用）。
3. **一键出报告**：工业场景最终要交的是质检单，不是 CSV。

---

## 四、我方界面（备用）的取舍

我们的版本（`app\`）优势是**流程简单、自测完备（73 项）**，劣势是**没有 part 约束、没有
设备连接、没有数据管理**。

**建议**：以他的界面为主界面（功能全），把我们已验证的东西移植过去：

| 我们已经验证好、值得移植的 | 移植难度 |
| --- | --- |
| 椭圆"总是尝试边缘精修"策略 | **已完成**（`scripts\patch_friend_engine.py`） |
| 双击某一行的放大核对视图 | 小（我们已有实现，可参考） |
| 73 项自测脚本（防止改崩） | 小（复制脚本 + 改导入路径） |
| 中文路径安全读写（`imageio_util`） | 小（照搬） |
