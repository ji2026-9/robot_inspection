# 机械臂智能视觉检测系统 —— 第一版 GUI

> 版本：v1.0　｜　位置：`E:\robot_inspection\app\`
> 模型：`E:\robot_inspection\weights\best.pt`（YOLO11n-Seg，单类别 `cylinder_bore`）

本程序**只做检测与任务编排**：不训练、不修改模型、不修改数据集、不修改原始测试图片。

---

## 1. 如何启动

**方式一（推荐）**：双击

```
E:\robot_inspection\app\run_gui.bat
```

**方式二**：命令行

```bat
cd /d E:\robot_inspection
"E:\robot_inspection\.venv\Scripts\python.exe" app\main.py
```

> 依赖：PySide6-Essentials（已安装在项目 `.venv` 中）、ultralytics、opencv-python、PyTorch。

## 2. 如何选择图片

点击底部 **【选择图片】** →
文件对话框默认打开 `E:\robot_inspection\test_images\`（手机测试照片），
可选 `.jpg / .jpeg / .png / .bmp`。选中后左侧立即显示原图（**不会修改原图**）。

## 3. 如何做 AI 自动检测（模式 A，默认）

1. 确认右上角 **【工作模式】** 选中的是 **★ AI 自动检测**；
2. 点击 **【开始 AI 检测】**；
3. 程序执行：`图片 → YOLO-Seg → mask → 最大轮廓 → 椭圆拟合 → 孔中心 → PCA 排序 → H01~H04`；
4. 左侧显示标注结果（mask 轮廓 / 椭圆 / 中心点 / H01~H04），
   右侧显示 **检测目标 4 / 已识别 n / 平均置信度**，并自动生成任务；
5. **若识别不足 4 个**：状态显示 **"检测不完整（n/4）"**，
   **不会生成任务、不会伪造缺失的孔**（例如测试3 在本模型 conf=0.50 下只能识别 3 个）。

## 4. 如何手动指定 H03（模式 B）

1. 先在模式 A 下点 **【开始 AI 检测】**（必须先得到检测结果）；
2. 把 **【工作模式】** 切到 **○ 手动指定检测**；
3. 在 **【手动指定】** 下拉框选择 **H03**；
4. 点击 **【生成检测任务】**；
   - H03 真实存在 → 状态显示 `目标已定位：H03  中心 (x, y)  置信度 0.xxx`，任务表出现一行 H03；
   - H03 不存在（例如测试3 只有 H01~H03）→ 显示 `当前图像中没有可靠定位到 H03。`，**不会伪造坐标**。

## 5. 如何模拟机器人执行

当前**没有真实机械臂**，所以：

- 机器人状态恒为 **"机器人：未连接"**（程序绝不假装已连接）；
- **【执行检测】**：点击后显示 `执行状态：机器人未连接，无法执行真实检测`，不会连接任何硬件；
- **【模拟执行】**：点击后逐个目标输出 `H0x -> 模拟完成（未连接真实机器人）`，
  任务表状态变为 **"模拟完成"**，用于完整演示流程。

## 6. 检测结果保存在哪里

每次检测（以及每次模拟执行）都会自动保存到**独立的时间戳目录**，绝不覆盖已有结果：

```
E:\robot_inspection\results\gui_runs\<YYYYmmdd_HHMMSS>\
    ├── <图片名>_result.jpg    检测结果可视化图
    └── detection.json         源图路径 / 检测时间 / H01~H04 / confidence / center_px /
                               orientation_status / 任务状态 / 警告与错误
```

也可以点 **【保存结果】** 手动再存一次。

## 7. 当前哪些功能依赖未来的工业相机 / 真实机器人

| 功能 | 现状 | 将来需要 |
|---|---|---|
| 图片来源 | 本地图片（`ImageFileCamera`） | 工业相机：只替换 `camera_interface.py` 的实现 |
| 机器人连接 | 永远"未连接"（`MockRobot`） | 真实机械臂：只替换 `robot_interface.py` 的实现 |
| 坐标转换 | **未实现** | 相机标定 + 像素→工件→机器人坐标（预留字段） |
| H01–H04 身份 | **仅"当前图像编号"** | 稳定的物理方向参考（见 `experiments\stable_hole_id\`） |

## 8. 重要声明（诚实性要求）

- 界面上的 `orientation_status` **恒为 `uncertain`**（当前没有可靠物理方向参考）；
- 已实测：把同一张图旋转 180°后，H01 与 H04 会对调（详见 `experiments\stable_hole_id\stable_hole_id_report.md`）；
- 因此 **H01–H04 是"当前检测任务中的编号"，不是永久物理身份**，不要用它直接指挥机器人测某个物理孔；
- 机器人状态**永远是"未连接"**，程序不会伪装已连接；
- 尚未完成毫米级坐标转换与机器人坐标转换，程序也不会假装完成。

## 9. 模块结构（便于后续替换）

```
app\
├── main.py               程序入口（含中文字体选择）
├── gui.py                界面（PySide6），只调用下面三个模块
├── vision.py             YOLO-Seg 推理 + 椭圆拟合 + PCA 编号 + 标注绘制
├── task_manager.py       任务生成/执行状态/结果保存
├── robot_interface.py    机器人接口（当前 MockRobot，永不假装连接）
├── camera_interface.py   相机接口（当前 ImageFileCamera / MockCamera）
├── config.py             路径与参数集中配置
├── selftest_headless.py  无界面自检（可自动跑完 4 张图）
└── run_gui.bat           双击启动
```

**替换工业相机** → 改 `camera_interface.py`；**替换真实机器人** → 改 `robot_interface.py`；
**GUI 与推理、任务、机器人三层互相独立**，不需要重构界面。

## 10. 已知实现细节

- 推理参数：`imgsz=640`、`conf=0.50`、`iou=0.70`；**GPU 优先，GPU 不可用自动回退 CPU**，并在日志中提示；
- `conf=0.50` 是**严格阈值**，不启用低阈值补检（因此测试3 会如实显示 3/4）；
- OpenCV 5.0 在 Windows 上无法用 `cv2.imread` 读取含中文的路径，
  本程序统一使用 `np.fromfile + cv2.imdecode`（`vision.imread_unicode / imwrite_unicode`）规避。

## 11. 图像显示与标注（v1.1 改进）

**照片区外观**

- 石板蓝渐变衬底 + 照片细描边 + 柔和投影（不再是黑块）；
- **【适应工件】** 复选框（默认开）：检测后自动放大到四个孔的外接区域；
- **缩放滑块** 100%~400%（默认 130%）：自由放大查看单个孔。

**标注为什么清晰**

界面上的 mask / 椭圆 / 中心点 / `H0x` 标签是在**显示画布坐标**里绘制的，
而不是烘焙在原始照片上 —— 因此无论图片是 2592×4608 还是放大到 400%，
文字大小恒定、始终可读；标签还带深色底衬条，压在工件纹理上也看得清。
（保存到磁盘的结果图仍使用图像坐标绘制，便于按原分辨率查看。）

**关于"孔为什么是椭圆"**

孔本身是**圆柱孔（物理上是圆）**，但照片是**斜视拍摄**的：圆在透视投影下必然变成椭圆，
这是几何事实而不是拟合误差。实测短/长轴比（越接近 1 越圆）：

| 图片 | H01 | H02 | H03 | H04 |
|---|---|---|---|---|
| 测试1 | 0.899 | 0.873 | 0.820 | 0.762 |
| 测试2 | 0.993 | 0.907 | 0.843 | 0.807 |
| 测试3 | 0.958 | 0.937 | 0.935 | — |
| 测试4 | 0.938 | 0.969 | 0.948 | 0.909 |

测试1/2 越往远端越"扁"（0.90 → 0.76），正是透视近大远小的表现；
测试4 接近正对拍摄，所以最接近圆（0.91~0.97）。

**拟合精度（实测）**：椭圆与 mask 轮廓的偏差（RMS 占短半轴百分比）
全都在 **0.9% ~ 2.6%**，面积比 0.998~1.000 —— 拟合本身是很准的。

> 修复记录：v1.0 曾把椭圆长短轴重新排序（max/min）却沿用原角度，
> 导致画出的椭圆被额外旋转约 90°，看起来"拟合很糟"（偏差最高达 21.6%）。
v1.1 起改为**保持 OpenCV 原始的 (轴, 角度) 配对**，仅额外提供 `major/minor/aspect` 字段，
偏差回落到 0.9%~2.6%。

## 12. 功能清单与快捷键（v1.2）

| 按钮 | 作用 | 快捷键 |
|---|---|---|
| 选择图片 | 打开文件对话框（默认 `test_images`，会记住上次目录） | `Ctrl+O` |
| 开始 AI 检测 | 推理 + 椭圆拟合 + H01~H04 编号 + 自动生成任务 + 自动保存 | `F5` |
| 生成任务：H0x | **仅手动指定模式可见**；只生成下拉框选中的那一个孔（不重新推理） | — |
| 执行检测 | 真实机器人接口（当前未连接，会明确拒绝） | — |
| 模拟执行 | 逐个目标模拟执行，任务状态变"模拟完成" | — |
| 保存结果 | 把当前结果写进新的时间戳目录 | `Ctrl+S` |
| 打开结果目录 | 用资源管理器打开本次结果目录 | — |
| 导出任务CSV | 导出 `tasks.csv`（同名自动改为 `tasks_02.csv`，不覆盖） | — |

**双击任务表的某一行** → 弹出该孔（H0x）的放大查看窗口（裁剪图 + 椭圆 + 中心 + 尺寸角度 + 长短轴比）。

### 为什么 AI 自动模式下看不到「生成检测任务」按钮

因为**在自动模式下它和「开始 AI 检测」完全重复**：`开始 AI 检测` 结束后会自动生成 4 个任务。
为了不让你点一个什么都不多做的按钮，v1.4 起：

* **AI 自动检测模式** → 该按钮**隐藏**；任务由检测自动生成（任务区显示 `任务：4 个（AI 自动）`）；
  想重新生成，直接重新检测即可（`F5`）。
* **手动指定检测模式** → 该按钮**显示**并改名为 `生成任务：H03`（跟着下拉框变），
  用来把选中的那一个孔变成任务（任务区显示 `任务：1 个（手动指定）`）。

另外：如果模式、目标孔、检测结果都没变，再点它也**不会重复生成**，会提示
`任务未变化：当前已是 N 个任务，未重复生成（避免清空执行状态）。`
—— 修掉了"模拟执行完再点生成任务会把状态清空回待检测"的问题。

**相机抽象已真正接入**：选图走的是 `camera_interface.ImageFileCamera`（`set_source → start → get_frame`），
所以将来换成工业相机时，只要实现同样的三个方法即可，GUI 无需改动。

## 14. 重要修复记录：中文路径图片读取失败（v1.3）

**现象**：打开软件后第一次点【选择图片】选到 `test_images\测试1.jpg`，日志出现
`图片读取失败（相机接口）`，照片区空白。

**根因（实测，非推测）**：`cv2.imread` 在本机（Windows + opencv-python 5.0.0）
**无法打开含中文的路径** —— 但它的行为会随"进程里是否已导入 ultralytics/torch"而改变。

用 `app\diag_imread.py` 实测：

| 时机 | 中文路径成功率 |
|---|---|
| 未导入 ultralytics 前 | **2 / 8**（中文路径全部失败） |
| 导入 ultralytics 之后 | **8 / 8** |

软件启动后模型是**懒加载**的（要等第一次检测才导入 ultralytics），
所以"先选图片"必然落在失败区间 —— 这就是为什么**第一张照片一定读不进去**，
而检测过一次之后就"莫名正常"了。

**修复**：所有用户图片路径统一走 `imageio_util.imread_unicode()`
（`np.fromfile + cv2.imdecode`），不再依赖 `cv2.imread` 的不确定行为。
涉及 `camera_interface.py`（相机层）、`vision.py`、`task_manager.py`（写图同理）。

**回归测试**：新增 `app\selftest_coldstart.py` —— 在**全新进程**里模拟真实用户顺序
（启动 GUI → 选图片 → 才检测），要求"模型尚未加载时也能读图"。
它已被并入总测试（F1 项）。当前：**65 / 65 全部通过**。

> 教训：主自测脚本当时先调用了 `det.load()`（导入了 ultralytics），
> 恰好绕过了失败区间，因此漏报。冷启动测试就是为了堵住这个盲区。

## 15. 模拟执行现在"看得见"了（v1.5）

以前点【模拟执行】只改任务表状态和日志，看不出它到底做了什么。现在会**逐孔动画演示**：

| 画面元素 | 含义 |
|---|---|
| 🟠 **橙色十字 + PROBE** | 模拟探头当前位置（会从上一个孔**平滑移动**到下一个孔） |
| 🟢 **绿色圆环 + 斜十字** | 该孔已完成模拟测量 |
| 🔵 **青色折线** | 规划的执行路径（H01 → H02 → H03 → H04） |
| 左下角 `SIMULATED RUN n/N (no real robot connected)` | 进度，并明确标注是仿真 |
| 底部 **模拟进度条** | 与任务表同步 |
| 日志 | 每个孔一行：`H04 移动到 (1318, 1096) -> 下探测量 -> 完成 [4/4]` |

**动画期间**：按钮变成 `停止模拟`，可随时中止；执行完**叠加层会保留**，方便截图留证；
加载新图片或重新检测时自动清除（同时把底部"执行状态"重置为"等待机器人连接"）。

**仍然是诚实的仿真**：机器人标签恒为 `机器人：未连接`；每次模拟都会提示
"这是软件仿真，机器人状态仍为未连接，不会驱动任何真实设备"；
保存的 `detection.json` 里带
`"execution": "simulated"`、`"execution_order"`、`"execution_done"`、
`"robot_layer_result"`（来自 `robot_interface.MockRobot`）以及
`"execution_note": "software simulation only - no real robot connected"`。
