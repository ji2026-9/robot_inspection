# 数据融合训练方案（FUSION_PLAN）

> 面向：收到本交付包的朋友
> 目标：把「交付方数据」与「你自己的数据」安全地合并训练，**不破坏任何一方 baseline**

---

## 0. 一句话结论

**不要直接把两个 `.pt` 文件强行拼接，也不要把两份 label 直接混在一起。**
正确做法是：**先验证 → 再审计 → 统一类别方案 → 再融合训练**。

---

## 一、三阶段流程

### 第一阶段：验证交付方的 best.pt

1. 运行 `verify\verify_package.py`，确认：
   - 包内文件齐全、SHA256 与 `docs\SHA256.txt` 一致；
   - 输出 `MODEL LOAD: PASS`。
2. 用 `inference\predict_holes.py` 对 `test_images\` 做一次推理，确认四个孔都能检出；
3. 记录结果（每张图检出孔数、每孔 confidence）。

### 第二阶段：验证你自己的模型

用你自己的数据与模型跑一遍同样的流程，得到**你自己的 baseline 结果**。

### 第三阶段：审计双方数据（关键，不能跳过）

按下表逐项核对。**任意一项不一致，都必须先处理，不能直接混合。**

---

## 二、数据审计检查清单（15 项）

| # | 检查项 | 为什么重要 | 你会怎么查 |
|---|---|---|---|
| 1 | **类别名称是否一致** | 名称不同（如 `bore` vs `cylinder_bore`）会导致概念混淆 | 对比双方 `data.yaml` 的 `names` |
| 2 | **class ID 是否一致** | 交付方 `0 = cylinder_bore`；你若把箱体外轮廓放 `1`，语义就变了 | 对比 `names` 的键值 |
| 3 | **标注格式是否一致** | 交付方是 **YOLO-Seg 多边形**（`class x1 y1 x2 y2 ...`）；你若用 bbox 或 COCO polygon 需先转换 | 打开任意 `.txt` 看一行 |
| 4 | **是否都是 cylinder_bore** | 若你的目标叫别的名字或含义不同，需先统一 | 抽样核对 |
| 5 | **是否都标注四个大型孔** | 若你有的图只标 1–3 个孔，混入后模型会学到"可以漏标" | 统计每张图的实例数 |
| 6 | **是否存在只标注部分孔的图片** | 同上，会直接伤害 Recall | 统计实例数分布 |
| 7 | **是否存在把小孔标成目标** | 小安装孔/螺纹孔混入会污染类别语义 | 抽查小目标 |
| 8 | **是否存在外轮廓标签** | 箱体外轮廓与"孔"是不同任务；混入会破坏语义 | 查看是否有大面积多边形 |
| 9 | **类别数量是否不同** | 2 类 vs 1 类 → 必须先设计统一类别方案 | 看 `nc` |
| 10 | **是否存在重复图片** | 重复会放大某类样本，甚至导致训练/验证泄漏 | 文件哈希去重 |
| 11 | **同一张/高度相似图片是否同时出现在 train 与 val/test** | **数据泄漏**会让指标虚高 | 感知哈希（dHash）跨 split 比对 |
| 12 | **图片分辨率** | 差异过大会影响 imgsz 下的细节可见性 | 统计分辨率分布 |
| 13 | **标注质量** | 多边形是否贴合孔边缘、是否漏点 | 抽样可视化叠加 |
| 14 | **数据采集角度** | 俯视/斜视比例差异会影响泛化 | 抽样目视 |
| 15 | **光照 / 反光情况** | 反光内壁是本项目已知的难点 | 抽样目视 |

> **特别提醒**：如果你除了孔之外还标注了**箱体外轮廓**，
> **不能**直接假定可以和交付方的单类别数据混合 —— 必须先确认双方 `data.yaml` 与 labels，
> 并设计统一类别方案（例如统一为 `0: cylinder_bore`，把外轮廓单独放到另一个实验）。

---

## 三、如果类别不同：统一类别方案的建议

1. **首选**：把双方都归一到
   ```
   names:
     0: cylinder_bore
   ```
   即"只保留孔"这一共同语义，其他类别**先剔除**（不要塞进同一实验的同一类别）；
2. 若确实需要多类别（例如以后要加"箱体"类），
   把类别表显式升级为多类，并把**双方 label 一起重映射**，先在**小规模**上验证编号正确；
3. **严禁**把不同 class ID 的 label 直接混在一起（同一个数字在不同数据集里含义不同）。

---

## 四、推荐融合实验设计

**不要覆盖 baseline。** 建议新建独立实验：

```
experiments\fusion_v1\
```

| 对比组 | 训练数据 | 说明 |
|---|---|---|
| Baseline | 交付方原有数据（20/2/3） | 已有，直接复用 |
| YourBaseline | 你自己的数据 | 你的对照 |
| **Fusion** | **交付方数据 + 你的数据** | 融合实验 |

训练后得到 `fusion_v1_best.pt`（放在 `experiments\fusion_v1\weights\`）。

**统一测试集**：

1. 交付方的 `test_images\`（4 张，保持不变）；
2. 双方共同认可的**独立测试集**（不能用训练过的图片）。

---

## 五、评估指标（至少比较这些）

| 指标 | 说明 |
|---|---|
| Precision | 检测精度 |
| Recall | 检测召回 |
| mAP50 | IoU=0.5 平均精度 |
| mAP50-95 | 更严格的平均精度 |
| **四孔完整检测率（4/4）** | **本项目最重要的工程指标** |
| 漏检数量 | 未检出的目标孔个数 |
| 误检数量 | 多检出的目标个数 |
| 最低目标孔 confidence | 最弱那个孔的置信度 |
| 平均目标孔 confidence | 整体置信水平 |

**尤其关注"四个孔是否全部检测到"** —— 工业测量场景里，漏一个孔就可能导致整个测量流程失败。

---

## 六、参考基线（交付方已测数据，供你对照）

| 项目 | 数值 |
|---|---|
| 交付模型 | YOLO11n-Seg，单类别 `cylinder_bore` |
| 训练数据 | train 20 / val 2 / test 3 |
| 训练配置 | imgsz=640, batch=2, epochs=100, patience=20, device=0, workers=2 |
| 5 个随机种子 × best/last × 4 张测试图 | **38/40 = 95%** 达到 4/4 |
| 目标孔 confidence 最小值 | 0.6233 |
| 已知难点 | 测试3 中一个**内壁高反光**的孔，置信度明显偏低；个别 checkpoint 下出现临界漏检（0.455/0.465，略低于 0.50） |

> 融合训练是否有效，建议用上面的指标做**同样口径**的对比，而不是只看某一张图。

---

## 七、禁止事项

1. ❌ 直接把两个 `.pt` 权重拼接/平均（不是模型融合的正确做法，通常无意义）；
2. ❌ 把不同 class ID 的 label 直接混合；
3. ❌ 在未做泄漏检查的情况下把相似图片同时放进 train 与 val/test；
4. ❌ 用自动伪标签替代人工标注（会引入系统性错误）；
5. ❌ 覆盖交付方的 baseline 或你自己的 baseline。
